## 1. 产品概述

### 1.1 背景

开发者需要一个长期维护、可对外分享的个人主页，用于替代简历附件与零散的社交账号，集中展示「我是谁、我会什么、我做过什么、我在想什么」。现有方案（模板建站、Notion 公开页、GitHub Profile）在视觉表达、内容控制力与专业度上不足。

### 1.2 产品定位

一个**深色星空主题、内容驱动、极简现代**的个人品牌站点。核心不是"炫技"，而是用克制的视觉语言让访客在 30 秒内建立对站主的专业认知，并顺畅地进入项目细节或建立联系。

一句话价值主张：**在星空下，快速认识一个工程师的作品与思考。**

### 1.3 产品目标

| 优先级 | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 访客在首屏 10 秒内理解站主身份与专长 | 首屏停留时长、简历/联系点击率 |
| G2 | 项目内容可被快速浏览并深入 | 项目卡片点击率、项目详情页平均阅读时长 |
| G3 | 博客成为可持续的内容资产 | 每月新增文章数、文章页访问量、RSS 订阅数 |
| G4 | 站点本身即是能力证明 | Lighthouse 性能/无障碍/SEO ≥ 95 |
| G5 | 内容维护成本低 | 新增一篇文章 ≤ 10 分钟，无需改代码结构 |

### 1.4 非目标（本期不做）

- 用户注册、登录、评论系统（避免运营与安全问题）
- 在线支付、会员、广告位
- 多作者协作与权限体系
- 亮色主题（本期仅深色，见 §5.2.1 说明）
- 站内即时通讯 / AI 客服

### 1.5 关键假设

1. 站点由站主一人维护，内容以 Markdown/MDX 文件形式存放于代码仓库。
2. 部署在静态托管平台（Vercel / Netlify / Cloudflare Pages 任一），无需自建服务器。
3. 首期单语言（简体中文），英文版作为 P2 迭代。
4. 内容量级：项目 5–20 个，文章 20–200 篇，技能 10–30 项。

## 2. 目标用户与场景

### 2.1 用户角色

| 角色 | 描述 | 核心诉求 |
| --- | --- | --- |
| 招聘方 / HR | 快速筛选候选人 | 30 秒判断技术栈与经验是否匹配，能拿到简历或联系方式 |
| 技术面试官 / 同行 | 评估真实能力 | 看项目细节、技术选型、代码与文章质量 |
| 潜在合作方 / 客户 | 判断是否可合作 | 看案例成果、服务范围、联系方式 |
| 站主本人 | 内容维护者 | 低成本发布与更新，数据可控 |
| 搜索引擎 / 社交平台爬虫 | 索引与预览 | 结构化数据、OG 图、sitemap、语义化 HTML |

### 2.2 核心使用场景

1. **快速扫描**：从社交媒体链接进入首页 → 浏览首屏介绍 → 滑动看技能与精选项目 → 点击"联系我"。
2. **深度评估**：进入项目列表 → 按技术栈筛选 → 打开项目详情 → 查看架构说明与线上地址。
3. **内容消费**：从搜索结果或 RSS 进入某篇文章 → 阅读 → 通过文末推荐进入其他文章。
4. **移动端碎片访问**：手机扫码打开 → 单手滑动浏览 → 一键复制邮箱 / 拨号 / 打开 GitHub。
5. **站主更新**：新增一个项目目录 + MDX 文件 → 提交 → 自动构建上线。

## 3. 信息架构

```
/                       首页（Hero + 技能摘要 + 精选项目 + 最新文章 + 联系）

/blog                   文章列表（分页 / 标签 / 搜索）
/blog/[slug]            文章详情（TOC / 代码高亮 / 上下篇）
/blog/tags/[tag]        标签聚合页
/tags                   标签总览（可选）
/uses                   装备与工具（P2，可选）
/contact                联系方式（可作为首页区块，独立页为 P2）
/404                    404 页
```

**导航策略**：桌面端顶栏固定（首页 / 项目 / 博客 / 关于），滚动时背景由透明过渡为半透明毛玻璃；移动端使用汉堡按钮 + 全屏抽屉。当前所在栏目高亮（Scroll Spy 或路由匹配）。

## 4. 核心功能需求

优先级定义：**P0** 首版必须；**P1** 首版应做；**P2** 后续迭代。

### 4.1 个人介绍（P0）

#### 4.1.1 Hero 首屏

- 展示：姓名/昵称、一句话定位（如「前端工程师 · 关注交互与性能」）、2–3 行简介、头像或抽象标识、状态徽标（如「在职 / 开放机会」）、主 CTA（查看项目）、次 CTA（下载简历 / 联系我）、社交链接（GitHub / 邮箱 / X / 掘金等，可配置显隐）。
- 背景为星空场景（见 §5.2.2），文字层需保证对比度，星空不得干扰阅读。
- 首屏高度：桌面 100vh 以内（避免 CTA 被挤出），移动端允许 `min-height: 100svh` 并压缩留白。
- 可选细节：打字机效果的职位轮播、鼠标视差（桌面端）、滚动提示箭头。

#### 4.1.2 关于我（/about）

- 富文本长文介绍（支持标题、列表、引用、图片、代码块）。
- 经历时间线：公司/组织、职位、起止时间（支持「至今」）、一句话成果、关联技能标签；按时间倒序，移动端纵向布局。
- 教育背景、证书/荣誉（可选模块，可在配置中开关）。
- 兴趣/日常（可选，用于人格化表达）。
- 页面底部固定"简历下载"与"联系我"入口。

#### 4.1.3 联系方式

- 邮箱：展示混淆后的地址（防爬虫），点击复制并 Toast 提示，或 `mailto:`。
- 社交链接：图标 + 悬浮名称，`rel="noopener noreferrer"`，外部链接新窗口打开。
- 可选：Calendly 等预约链接、微信二维码（点击展开）。

#### 4.1.4 简历下载

- 提供 PDF 静态文件，文件名含版本与日期（如 `resume-zh-2026-10.pdf`）。
- 点击触发下载并记录事件；文件缺失时按钮置灰并隐藏（构建期校验）。

### 4.2 技能展示（P0）

- **分类展示**：如「前端 / 后端 / 工程化 / 设计 / 工具」，每个分类下为技能条目。
- **条目信息**：名称、图标（可选）、熟练度或角色标签（推荐用「熟练 / 熟悉 / 了解」三档文本，避免虚构百分比）、可选一句话说明（用在哪、做过什么）。
- **交互**：分类 Tab 切换或分组直接铺开（条目 ≤ 15 时直接铺开，减少一次点击）；悬浮时高亮同分类条目；点击条目可筛选出相关项目（P1）。
- **视觉**：胶囊标签或卡片网格；图标统一风格与尺寸；不使用进度条动画堆叠造成视觉噪音。
- **内容规范**：技能必须与项目/经历可对应，禁止列出未实际使用的技术。

**验收标准**

- [ ] 技能数据来自单一配置文件，新增技能无需改动组件。
- [ ] 分类数量 1–6 个、技能总数 ≤ 30 时布局不塌陷，移动端单列/双列自适应。
- [ ] 无 JS 时技能内容仍可见（SSR/SSG 渲染）。

### 4.3 项目展示（P0）

#### 4.3.1 项目列表（/projects）

- 卡片字段：封面图（或渐变占位）、项目名、一句话简介、技术栈标签（最多展示 4 个 + `+N`）、年份、状态（线上 / 开源 / 归档）、精选标记。
- 交互：点击整卡进入详情；悬浮时封面轻微缩放/亮度提升 + 边框高光；键盘可聚焦（`:focus-visible`）。
- 筛选与排序（P1）：按技术栈标签多选筛选、按年份或精选排序；筛选状态写入 URL query，可分享、可刷新保留。
- 空状态：无匹配结果时展示提示与"清除筛选"按钮。
- 分页：首版一次性展示（≤ 20 个），超过后使用"加载更多"或分页。

#### 4.3.2 项目详情（/projects/[slug]）

- 内容区：项目背景与问题、我的角色、方案与架构、难点与取舍、结果与数据、截图/演示 GIF、技术栈、仓库与线上链接。
- 结构：顶部标题 + 元信息（时间、角色、技术栈、链接）→ 正文（MDX）→ 相关项目推荐 → 返回列表。
- 支持图片灯箱查看（P1）。
- 无正文时降级为卡片信息展示，不出现空白页。

#### 4.3.3 内容模型

```ts
interface Project {
  slug: string;            // 唯一，URL 使用
  title: string;
  summary: string;         // 一句话简介，≤ 60 字
  cover?: string;          // 16:9 或 4:3，提供 blur 占位
  tech: string[];          // 技术栈标签
  year: number;
  role?: string;
  status: 'live' | 'oss' | 'archived';
  featured?: boolean;      // 首页展示
  links?: { demo?: string; repo?: string; article?: string };
  body: string;            // MDX
  order?: number;          // 手动排序权重
}
```

**验收标准**

- [ ] 新增项目 = 新增一个 MDX 文件 + 一张封面图，构建后自动出现在列表与 sitemap。
- [ ] 所有外链可点击区域 ≥ 44×44px（移动端）。
- [ ] 缺封面时使用确定性渐变占位（同一项目每次渲染颜色一致）。

### 4.4 博客（P0）

#### 4.4.1 文章列表（/blog）

- 列表项：标题、摘要、发布日期、阅读时长（按字数估算）、标签、封面（可选）。
- 支持置顶（`pinned: true`）与草稿（`draft: true`，构建时不输出）。
- 分页或"加载更多"，每页 10 篇；分页状态写入 URL。
- 标签筛选、按年份归档（P1）。

#### 4.4.2 文章详情（/blog/[slug]）

- 排版：正文最大宽度 680–760px，行高 1.75–1.9，段间距 ≥ 1em。
- 目录（TOC）：桌面端右侧吸附，滚动高亮当前章节；移动端折叠为顶部"目录"按钮。
- 代码块：语法高亮、行号可开关、一键复制、横向滚动不撑破布局、支持文件名标签。
- 图片：`figure` + `figcaption`，懒加载，点击放大。
- 阅读进度条（顶部细线，P1）。
- 文末：作者卡片、上一篇/下一篇、相关文章（同标签，最多 3 篇）。
- 分享：复制链接；可选生成分享图（P2）。
- 文章内锚点链接可复制。

#### 4.4.3 内容与订阅

- MDX frontmatter 字段：`title / date / summary / tags / cover / draft / pinned / updated`。
- RSS（`/rss.xml`）与 sitemap 自动生成，仅包含已发布文章。
- 站内搜索（P1）：构建期生成静态索引，支持标题/摘要/标签模糊匹配；无结果时给出提示。
- 文章更新需显示「最后更新于」；日期使用 `<time datetime>`。

**验收标准**

- [ ] 一篇含 3 个代码块、5 张图片、10 个标题的文章在移动端无横向溢出。
- [ ] 关闭 JavaScript 后正文、TOC 锚点、代码内容仍完整可读。
- [ ] 草稿不会出现在列表、RSS、sitemap 与搜索结果中。

### 4.5 全局与通用能力

| 功能 | 优先级 | 说明 |
| --- | --- | --- |
| 响应式适配 | P0 | 手机 / 平板 / 桌面 / 宽屏四档，见 §5.3 |
| 星空背景 | P0 | 全局固定背景层，见 §5.2.2 |
| 深色主题 | P0 | 仅深色，`color-scheme: dark`，禁用系统亮色覆盖 |
| 页面过渡 | P1 | 路由切换淡入 + 内容上移 8px，时长 ≤ 300ms |
| 滚动动效 | P1 | 元素进入视口时渐显，`IntersectionObserver`，只做一次 |
| 加载骨架 | P1 | 图片与列表骨架屏，避免布局抖动 |
| 404 页 | P0 | 星空场景 + 返回首页/博客入口，HTTP 404 |
| 错误兜底 | P1 | 组件级错误边界，图片加载失败占位 |
| 站内搜索 | P1 | 见 §4.4.3 |
| RSS | P1 | 自动生成并提供订阅入口 |
| 主题切换 | P2 | 亮色主题需重新设计星空与配色，暂不做 |
| 访问统计 | P1 | 隐私友好方案（如 Umami / Plausible），不采集个人身份信息 |
| 国际化 | P2 | 中/英双语路由，`hreflang` |
| 命令面板 | P2 | `Cmd/Ctrl+K` 搜索页面与文章 |
| 背景音乐 | P2 | 默认关闭，需用户主动开启 |

### 4.6 内容管理

- 首版采用 **Git 驱动的静态内容**：`content/projects/*.mdx`、`content/blog/*.mdx`、`data/profile.ts`、`data/skills.ts`。
- 构建期通过 schema 校验 frontmatter，字段缺失或类型错误直接构建失败并给出明确报错。
- 图片统一放入 `public/images/`，命名 `kebab-case`，提供 WebP/AVIF 与尺寸信息。
- 可选接入无头 CMS（P2），但必须保持内容可回迁为文件，避免锁定。

## 5. 设计要点

### 5.1 设计原则

1. **暗而不闷**：深色不等于纯黑，用层级色与低饱和光晕营造空间感。
2. **星空是背景，不是主角**：动效克制、对比度优先，任何装饰不得降低文字可读性。
3. **内容先行**：视觉服务于信息密度与浏览效率，避免大面积无意义留白和过度动效。
4. **一致的物理感**：统一的圆角、边框、光晕与动效曲线，形成可识别的系统。
5. **性能即体验**：动效与背景必须可降级，低端设备不掉帧。

### 5.2 视觉规范

#### 5.2.1 色彩

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg-base` | `#070A12` | 页面最底层 |
| `--bg-deep` | `#0A0F1C` | 星空渐变底色 |
| `--surface-1` | `#111827` | 卡片、面板 |
| `--surface-2` | `#161F33` | 悬浮/激活态 |
| `--border` | `rgba(255,255,255,0.08)` | 分割线、卡片描边 |
| `--border-strong` | `rgba(255,255,255,0.16)` | 悬浮描边 |
| `--text-primary` | `#E8EEF9` | 标题与正文（对比度 ≥ 12:1） |
| `--text-secondary` | `#A3B0C6` | 摘要、辅助信息（≥ 7:1） |
| `--text-muted` | `#6B7A93` | 时间、占位（≥ 4.5:1） |
| `--accent` | `#6EA8FE` | 主行动色（星蓝） |
| `--accent-2` | `#A78BFA` | 次强调（星紫） |
| `--accent-warm` | `#F5C98B` | 少量点缀（流星金） |
| `--glow` | `rgba(110,168,254,0.25)` | 光晕、聚焦环 |
| `--danger` | `#F87171` | 错误 |
| `--success` | `#4ADE80` | 成功提示 |

规则：

- 强调色只用于可交互元素与关键数字，全屏同时出现的强调色面积 ≤ 8%。
- 渐变仅用于标题文字（蓝→紫，角度 120°）与光晕，不用于大面积背景填充。
- 禁止在正文上叠加星空粒子；正文区域加 `background: rgba(7,10,18,0.72)` + `backdrop-filter: blur(8px)` 保证对比度。
- 语义色不得仅靠颜色区分，需配合图标或文字。

#### 5.2.2 星空背景实现规范

**分层结构（由远到近）**

| 层 | 内容 | 动效 |
| --- | --- | --- |
| L0 | 深空渐变（顶部 `#0A0F1C` → 底部 `#070A12`）+ 两处极淡星云径向渐变 | 静止 |
| L1 | 远景星点（直径 0.5–1px，约 120–180 颗，透明度 0.2–0.5） | 缓慢闪烁（3–6s 随机周期） |
| L2 | 近景星点（直径 1–2px，约 40–70 颗，透明度 0.4–0.8，部分带 2px 光晕） | 闪烁 + 滚动视差（位移系数 0.05） |
| L3 | 偶发流星（间隔 6–15s，随机位置与角度） | 一次划过，≤ 1.2s |
| L4 | 页面内容 | — |

**技术要求**

- 使用 Canvas 2D 绘制 L1–L3，单 canvas 固定定位 `position: fixed; inset: 0; z-index: 0; pointer-events: none`。
- 按 `devicePixelRatio` 缩放画布，上限 2，避免高分屏过度绘制。
- 星点数量按视口面积计算并设上限（移动端 ≤ 120 颗，桌面 ≤ 250 颗）。
- 使用 `requestAnimationFrame`，页面 `visibilitychange` 隐藏时暂停；静止状态下若 3 秒无交互可降帧到 30fps。
- 尊重 `prefers-reduced-motion: reduce`：停止闪烁、流星与视差，仅保留静态星点。
- 不支持 Canvas 或 JS 失败时，降级为 CSS `radial-gradient` 星点纹理（预生成 1 张 ≤ 20KB 的 WebP）。
- 星点颜色仅取 `#FFFFFF` / `#CFE0FF` / `#E6D9FF` 三色，避免彩色噪点。
- 流星拖尾使用线性渐变，长度 ≤ 160px，不产生持续残影。
- 移动端滚动时不得触发 canvas 重排；canvas 不参与文档流。

**视觉验收**

- [ ] 首屏文字区域任意位置，背景与文字对比度满足 WCAG AA。
- [ ] 星空动画下，中端手机滚动帧率不低于 50fps。
- [ ] 截图静止时星空分布自然，无规则的网格或重复纹理。

#### 5.2.3 字体与排版

- 中文：`"PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`
- 英文/数字：`Inter, "Space Grotesk", system-ui`（标题可用 Space Grotesk 提升几何感）
- 代码：`"JetBrains Mono", "Fira Code", ui-monospace, monospace`
- 字号阶梯（桌面 / 移动）：12/12、14/14、16/16、18/17、24/21、32/28、44/34、64/40（px）
- 行高：正文 1.75，标题 1.2–1.3，UI 文本 1.5
- 字重：正文 400，强调 500，标题 600–700；中文字体避免使用 300 以下字重
- 字间距：大标题 `-0.02em`，正文 0；中文正文不使用斜体
- 段落最大宽度 72ch（文章 68ch），标题最大 20 字/行

#### 5.2.4 间距、圆角、描边、阴影

- 间距基数 4px，常用阶梯：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96。
- 页面容器：`max-width: 1200px`，左右内边距 移动 20px / 平板 32px / 桌面 48px。
- 圆角：小控件 8px，卡片 14px，大容器 20px，胶囊 999px。
- 描边：默认 1px `--border`；悬浮 1px `--border-strong` + `box-shadow: 0 0 0 1px rgba(110,168,254,0.18), 0 8px 32px rgba(0,0,0,0.45)`。
- 阴影保持低对比、大扩散，避免"浮起卡片"的廉价感。

#### 5.2.5 图标与插画

- 统一线性图标（1.5px 描边，24×24 网格），优先用同一图标库（如 Lucide）。
- 项目封面统一比例 16:9，统一色调处理（轻微降饱和 + 深色遮罩），确保与暗色背景融合。
- 头像建议圆形或圆角方形，尺寸 96–128px，带 1px 光圈描边。

#### 5.2.6 动效规范

| 场景 | 时长 | 曲线 |
| --- | --- | --- |
| 悬浮 / 聚焦反馈 | 150ms | `ease-out` |
| 展开 / 收起 | 220ms | `cubic-bezier(0.16,1,0.3,1)` |
| 路由切换 | 260ms | `ease-out` |
| 滚动渐显 | 400ms | `ease-out`，位移 ≤ 12px |
| 页面加载（首屏元素） | 500ms | 依次延迟 60ms，最多 3 级 |

- 动效只做"进入"，不做反复循环（星空除外）。
- 所有动效必须可被 `prefers-reduced-motion` 关闭。
- 不使用阻塞滚动的整屏动画、不使用鼠标跟随的强视差。

### 5.3 响应式适配

| 断点 | 宽度 | 布局策略 |
| --- | --- | --- |
| Mobile | < 640px | 单列；导航为抽屉；Hero 高度 `100svh`；卡片全宽；TOC 折叠；触控目标 ≥ 44px |
| Tablet | 640–1023px | 两列卡片；容器内边距 32px；技能 2 列；文章正文居中 |
| Desktop | 1024–1439px | 项目 3 列 / 技能 3–4 列；右侧 TOC；导航横向 |
| Wide | ≥ 1440px | 容器 1200px 居中；增加上下留白；Hero 内容垂直居中 |

适配规则：

- 使用 CSS Grid/Flex + `clamp()` 实现流式字号与间距，减少断点硬切。
- 图片使用 `srcset` + `sizes`，`aspect-ratio` 固定占位防抖动。
- 移动端禁用 hover 效果，改为 `active` 反馈；不使用仅靠 hover 才可见的信息。
- 横屏手机（高度 < 500px）压缩 Hero，隐藏滚动提示。
- 支持 200% 浏览器缩放不出现横向滚动。
- 触摸设备上 canvas 不监听 mousemove，避免无效计算。

### 5.4 可访问性（WCAG 2.1 AA）

- 全站键盘可达：Tab 顺序符合视觉顺序，焦点环清晰（2px `--accent` + 2px offset），提供"跳到主内容"链接。
- 语义化结构：`header / nav / main / article / section / footer`，每页仅一个 `h1`。
- 图片必须有 `alt`；纯装饰图 `alt=""`；图标按钮有 `aria-label`。
- 星空 canvas 设 `aria-hidden="true"`。
- 移动端抽屉打开时锁定焦点、`Esc` 关闭、关闭后焦点回到触发按钮。
- 表单/搜索框有关联 `label`，错误提示用 `aria-live`。
- 正文对比度 ≥ 7:1，辅助文字 ≥ 4.5:1。

### 5.5 性能规范

| 指标 | 目标 |
| --- | --- |
| LCP（4G，中端机） | ≤ 2.0s |
| INP | ≤ 200ms |
| CLS | ≤ 0.05 |
| 首屏 JS（gzip） | ≤ 150KB |
| 首屏图片总重 | ≤ 300KB |
| Lighthouse 性能 / 无障碍 / 最佳实践 / SEO | 均 ≥ 95 |

手段：SSG 预渲染、路由级代码分割、字体 `font-display: swap` 且子集化、图片 AVIF/WebP + 懒加载、星空动画空闲时降帧、第三方脚本延后加载且总数 ≤ 2 个、开启 Brotli 与长缓存。

### 5.6 SEO 与分享

- 每页唯一 `title`（≤ 60 字符）与 `description`（≤ 160 字符）。
- 结构化数据：`Person`（首页）、`BlogPosting`（文章）、`BreadcrumbList`（详情页）。
- Open Graph / Twitter Card：自动生成 1200×630 分享图（项目名/文章标题 + 星空底 + 站点标识）。
- `sitemap.xml`、`robots.txt`、规范链接（canonical）、RSS。
- URL 使用小写英文短横线，不含日期与 ID；修改标题时保留旧 slug 并做 301。

## 7. 数据结构与配置

```ts
// data/profile.ts
interface Profile {
  name: string;
  handle: string;
  headline: string;              // 一句话定位
  bio: string[];                 // 2–3 段
  avatar: string;
  location?: string;
  status?: { label: string; available: boolean };
  socials: { label: string; href: string; icon: string }[];
  resume?: { zh?: string; en?: string };
  email: string;
}

// data/skills.ts
interface SkillGroup {
  id: string;
  name: string;                  // 分类名
  items: {
    name: string;
    level: 'proficient' | 'familiar' | 'learning';
    note?: string;               // 一句话说明
    icon?: string;
    relatedProjects?: string[];  // project slug
  }[];
}

// content/blog/*.mdx frontmatter
interface PostMeta {
  title: string;
  date: string;                  // ISO
  updated?: string;
  summary: string;
  tags: string[];
  cover?: string;
  draft?: boolean;
  pinned?: boolean;
  lang?: 'zh' | 'en';
}
```

配置约束：`profile.ts` 与 `skills.ts` 通过 zod（或等价方案）在构建期校验；所有外链统一走 `isExternal` 判断并自动加安全属性。

## 8. 非功能需求

1. **兼容性**：最近两个大版本的 Chrome / Edge / Safari / Firefox；iOS Safari 15+；Android Chrome 100+。不支持 IE。
2. **可用性**：静态托管可用性依赖平台 SLA；构建失败不覆盖线上版本。
3. **安全**：全站 HTTPS；外链 `rel="noopener noreferrer"`；不引入未经审计的第三方脚本；CSP 允许 `self` 与本域资源。
4. **隐私**：统计不采集 cookie 级个人标识，提供隐私说明（P1）。
5. **可维护性**：内容与组件分离；组件具备 props 类型与默认值；关键逻辑有注释；目录结构见 §9。
6. **可扩展**：新增栏目只需增加路由与内容集合，不修改全局布局。

## 11. 风险与待确认项

| 风险/问题 | 影响 | 建议 |
| --- | --- | --- |
| 星空动效导致低端机掉帧、耗电 | 体验与性能指标不达标 | 分档渲染 + 面积/设备上限 + 可降级为静态纹理 |
| 深色低对比导致长文阅读疲劳 | 阅读完成率下降 | 正文区域提高背景不透明度，控制行宽与行高，提供"专注阅读"模式（P2） |
| 技能等级表述主观 | 可信度受损 | 用三档文本 + 关联项目佐证，避免百分比 |
| 博客长期断更 | 站点显得停滞 | 首页展示最近更新时间，先保证 5–8 篇高质量文章再上线 |
| 内容增长导致构建变慢 | 发布效率下降 | 内容 > 200 篇时引入增量构建或按需渲染 |
| 待确认：站点语言与域名 | 影响 SEO 与文案 | 需站主确认中/英策略与最终域名 |
| 待确认：是否接入无头 CMS | 影响内容管线复杂度 | 首版文件驱动，保留迁移接口 |

## 12. 附录：页面线框说明

**首页（自上而下）**
1. 固定顶栏（透明 → 滚动后毛玻璃）
2. Hero：状态徽标 / 姓名 / 定位 / 简介 / 两个 CTA / 社交图标，背景星空
3. 技能摘要：4–6 个核心技能胶囊 + "查看全部"
4. 精选项目：2–3 张大卡（左图右文或上图下文）
5. 最新文章：3 条列表（标题 + 日期 + 阅读时长）
6. 联系区：一句话邀请 + 邮箱复制 + 社交链接
7. 页脚：版权、备案（如需）、RSS、回到顶部

**项目列表页**：标题与简介 → 筛选栏（P1）→ 卡片网格 → 加载更多
**项目详情页**：面包屑 → 标题 + 元信息 → 封面 → 正文 → 链接区 → 相关项目
**博客列表页**：标题 + 订阅入口 → 置顶文章 → 文章列表 → 分页
**文章详情页**：面包屑 → 标题 + 日期 + 阅读时长 + 标签 → 正文 + 右侧 TOC → 作者卡 → 上下篇
